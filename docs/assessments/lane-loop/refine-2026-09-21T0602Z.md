## 0. Finding: a devbox CLI ahead of the served authority cannot write notes

The first `item note` this tick attempted failed with "Additional properties are not allowed
('acked_by', 'predecessor_session', 'release_digest', 'worktree_host' were unexpected)". Cause,
read at the source: `sprintctl/served.py` `item_note` sends the four S6 checkpoint keys
unconditionally, as None, since f3e8371 (#2473, PR #81), so they are present in v0.7.1 and
v0.7.2 and absent in v0.7.0; the served `work.item.note` schema on 0.1.69 is
`additionalProperties: false`. Every note type is affected, not only `lane.checkpoint`, so a
lane loop running a 0.7.1+ CLI against 0.1.69 cannot record dispatch or review notes at all.
The 05:52 UTC note 3525 was the last one written before the upgrade; the upgrading process is
not identifiable from the two implement session files (neither contains a `uv tool install`
command), and the loop's preflight only probes `sprint list`.

Applied here: the devbox CLI was pinned back to **v0.7.0** (`uv tool install --force
--reinstall "sprintctl[remote,served] @ git+file:///projects/dev/sprintctl@v0.7.0"`; receipt now
records `rev=v0.7.0`), which is the version the 0.1.69 authority was rolled for (#2444). A probe
note was accepted immediately (event 3530 on #2504). The 0.7.0 `item note` has no `--json`
option; two retries that passed it failed silently until re-run without it. Filed **#2508**
(fast-build, sprintctl) to omit the keys when unset, and rewrote #2502 so step (5) upgrades both
hosts after the roll (section 2). Both items say not to reinstall from the checkout directory
