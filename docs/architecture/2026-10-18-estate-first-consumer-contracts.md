# EC-01 first-consumer contract extraction

This is a **partial source extraction**, building on the [EC-01 source-census seed](2026-10-18-estate-source-interface-census.md). It follows one concrete source path through Agentops, Vuoro, and Sprintctl, then pins representative Go, Rust, and TypeScript interfaces relevant to EC-00. It is not an owner attestation, a complete consumer graph, a deployment register, or evidence of live use.

The machine-readable companion contains exact source commits and SHA-256 hashes for every inspected file. Its large Sprintctl catalog and CLI sections are immutable, descriptive snapshots from the recorded source commit: they are not a generated IDL, a migration target, or a claim about the current deployed API. It also includes the 106 source-exported Sprintctl work-operation definitions, the 67 served CLI-to-operation routes, 97 served-mode command dispositions, and the emitted `sprintctl agent-protocol --json` value. The catalog snapshot was generated by invoking `sprintctl.vuoro_adapter.catalog_operation_specs(resource_schema_available=True)` from the pinned Sprintctl source. Three maintenance-resource operations are conditional and omitted by the same function when `resource_schema_available=False`; this source superset is not a claim that a running service advertises all 106. The companion records a reproducible checker: supply all seven source checkouts with the referenced commits available, and use Sprintctl at its pinned commit with its Python 3.12 `uv.lock` environment (`vuoro-adapter-kit` 0.2.2). After environment provisioning, the checker verifies every recorded source hash, re-invokes the true/false catalog exports, compares route/disposition constants, and runs the pure `agent-protocol --json` command through Click. The checker itself makes no network or backend calls.

## The first owner path

The source edge is Agentops `VuoroOwner` → `vuoro_client.AsyncVuoroClient` → Vuoro HTTP v1 → the Sprintctl work catalog. The host adapter declares fourteen direct owner calls for agent directory, inbox, and run delegation. Each call supplies a repository identity, with envelope idempotency keys forwarded only where the adapter does so. Sprintctl’s exported work definitions own the operation input/result JSON Schemas, required authority, read/write/admin/enqueue semantics, idempotency requirement, and repo scope. The adapter does not own work, message, run, or grant persistence.

The source records do **not** identify the Agentops checkout’s installed `vuoro_client` package revision; the host adapter imports it lazily and this repository does not declare a version pin. Likewise, there is no deployment or runtime catalog observation here. The operation catalog revision is calculated from the entire composed Vuoro catalog, so this source extraction does not invent a deployed revision from the Sprintctl subset.

Vuoro’s service shell declares handshake, catalog and invoke v1 endpoints. Invocation results carry accepted/rejected/error states in a versioned envelope. The service checks catalog revision, operation schema, repository scope, required authority and per-operation idempotency before dispatch. Its catalog revision is a SHA-256 of canonical serialized operations, extended by resource-kind and observation-transport declarations when present.

## CLI and MCP bindings

Sprintctl’s source contains 67 exact served command routes and classifies 97 Click leaves as catalog-backed, local or unavailable in served mode. `agent-protocol --json` is a separate local machine interface (protocol v3); its source explicitly states reservations are advisory and overlapping reservations are allowed. Agent, message and run verbs are served-only and call the named work operations. The embedded route map records option-dependent mappings such as `next-work` with or without `--project`.

Vuoro’s MCP edge has two fixed base tools: `list_ready_work` → `work.public.list-v1` and `describe_work` → `work.public.item-v1`, both under `work:read`. It also declares source-conditional record, coordinate, effect, effect-read and work-link toolsets. Those may disappear from the active MCP list when their owner registry or required operation is unavailable. Tool failures are structured tool results with `isError: true`; they are not empty reads. No deployed MCP tool list or caller population was read.

Vuoro’s `acceptance_explanation` also imports Agentops’ public `operator-projection` 0.2.5 package from a SHA-256-pinned wheel. Its declared API reconstructs a read-only P1 view from Sprintctl effect, release, item-decision, and lease reads, then presents the result; the package explicitly describes itself as derived and read-only. This is a concrete cross-repository producer/consumer edge, not effect-acceptance authority. The wheel and source release are pinned in the JSON; whether that dependency is installed or invoked in a running edge remains unknown.

Two source comments should be reconciled during owner review. Agentops’ `OwnerPort` docstring says “eleven owner operations,” while its current method declarations and implementation contain fourteen. Vuoro’s public MCP contract comment points at Sprintctl commit `9f92190`; this extraction binds the current operation definitions to Sprintctl commit `95f8fed` and their exact source hashes instead of relying on that older reference.

These examples provide concrete Go, Rust and TypeScript source boundaries for EC-00 interoperability cases. They do not imply that these projects consume the first work API path or that their protocols should be replaced. The estate requirements keep external/native APIs behind explicit adapters and direct browser/native bindings to be inventoried and qualified. No architecture option or IDL is selected here.

## Disposition and limits

The governing target plan, rather than a consumer-count finding, determines legacy direction: ActionQ’s runner/queue/daemon remain retired while its harvested invariants remain useful; the target plan schedules kctl/metanarrative stores for S4 retirement and dispatch manifests plus `sync_skills.py` for S6 retirement. This does not assert that installed residue or consumers have disappeared. The exact target citations are in the JSON.

This increment did not read deployment configuration, active runtime catalogs, credentials, live traffic, retention settings, event subscriptions, consumer populations, or other installed packages; the pinned projection wheel is a declared dependency only, not an installation observation. The public source set reuses the 18 October visibility allowlist without re-querying it and includes only repositories marked public there. Private and visibility-unverified details remain outside this artifact. Operation ownership is source-bound; authentication principals, deployment scopes, actual persistence, retries in production, compatibility windows, target package, per-interface migration/rollback and shim expiry remain unresolved wherever source does not define them. EC-01 remains partial.
